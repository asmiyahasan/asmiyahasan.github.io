Predator vs Prey

Two agents learned to chase and to hide by playing tens of thousands of games against each other. This page covers how the game works, what the experiments showed, and how a new model gets from my laptop to the version you can play.

The game

A predator and a prey move around a 10 × 10 arena with four blocks in it. Each step (ten per second), both pick one of nine moves: eight directions or stay still. The predator wins by touching the prey within 30 seconds; the prey wins by surviving.

Both have the same top speed, but the prey accelerates faster, so it can out-turn the predator. Rewards are zero-sum: every step the prey survives is worth +0.01 to it and −0.01 to the predator, and a catch is worth +1 to the predator and −1 to the prey.

Each agent sees 28 numbers every step:

  • its own position and velocity
  • 16 rays measuring the distance to the nearest wall or block in every direction
  • the opponent's position and velocity, but only when no block is in the way
  • where it last saw the opponent, and how long ago

Training

The environment is written in Python with the PettingZoo multi-agent interface, and the agents are trained with PPO from Stable-Baselines3. Training is self-play: the predator trains against a pool of earlier prey, then the prey trains against a pool of earlier predators, and so on for ten generations. Keeping old opponents in the pool stops each side forgetting how to beat strategies it has already seen.

Before any learning, I built scripted baselines (a chaser that runs straight at the prey and a fleer that runs straight away) to check the environment worked and to measure trained agents against.

What the experiments showed

The interesting part was balance: whichever side found a reliable strategy would win every game, and a game one side always wins is no fun to play against. Each change below was a response to what the previous run showed.

Setup What happened Predator's catch rate
Open arena, predator 10% faster The predator worked out how to corner the prey and never lost again. 100% from generation 3
Open arena, equal speeds A real contest for five generations, then the predator broke through. 0–28%, then 100%
Four blocks and raycast vision The prey learned to break line of sight behind blocks. The predator had no memory, so once the prey was hidden it had no idea where it had gone. Up to 84%, then down to 3%
Blocks plus "last seen" memory The most even match: around half of games went each way in the middle generations, before the prey edged ahead again. 48–55% at generations 6–8

Catch rates are for the latest predator against the latest prey, over 200 games with fixed starting positions.

From training to the browser

There is no server: the trained networks run in your browser. That meant rewriting the game in TypeScript, and the risk of a port is that it is almost the same. An agent playing a game that is 1% different from the one it trained in can quietly play badly.

Two kinds of file keep the Python and TypeScript versions honest:

  • Parity fixtures: recorded games from Python, with every position, observation and reward. The website's tests replay them and require the TypeScript game to match to within rounding.
  • Model test vectors: each exported network carries sample inputs and the exact outputs Python computed, and the website checks it reproduces them.

Getting a new model live

A new model goes through the same steps every time, and each one can stop it:

  1. Export. The network is converted to JSON and checked to choose the same action as the original on thousands of steps.
  2. Evaluation gate. The new model plays 300 games against the current champion. It is only promoted if it beats the champion by at least 3 percentage points and still beats the scripted baselines.
  3. Release. Champions are published as a versioned GitHub Release with the models, parity fixtures, a model card and the gate report.
  4. Pull request. A GitHub Actions workflow opens a pull request on the website repository with the new files.
  5. Checks and deploy. The website's CI runs every parity test against the new files. Merging deploys the site to GitHub Pages.

The gate earned its place on its first real run: generation 8 had been the most evenly matched pair in training, but against the generation 10 champion its prey survived 37.7% of games where the champion survived 82.3%, so it was rejected.
